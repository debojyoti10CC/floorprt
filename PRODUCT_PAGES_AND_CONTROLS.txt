AQRA — CURRENT INTERFACE AND DATA
Last updated: 2026-11-06

PRODUCT
AQRA uses public prediction-market trader history for research and credit screening. Trader P&L is not collateral. Borrower bond is the only pledged asset in the trader-credit demo.

SIDEBAR
- Data opens the observed wallet-history benchmark.
- Risk engine opens the stress model inside Data and scrolls to its results.
- Borrow opens the request composer and the connected borrower's requests.
- Lend opens the onchain request list and lender controls.
- Whitepaper opens the in-app protocol paper.
- The wallet card opens account connection. The bottom status reports RPC connectivity and chain.

DATA
- Wallet histories reports successful histories and daily observation count.
- Walk-forward rounds reports the sample period and capture profile.
- Polymarket fills reports observed market fills and resolved-sample coverage.
- The outcome chart and policy rows report next-month realized trader P&L, active observations and profitable-wallet frequency. They do not show lender returns.
- Export data downloads the current underwriting JSON.
- Decision month filters sampled wallets and policy comparisons by UTC cutoff.
- Selection policy filters the public-wallet table.
- Wallet search filters that table by address.
- Previous/Next paginate. Selecting an address shows dated windows, score status, next-month P&L, largest sampled settled buy and evidence digest. A known buy links to its Polygon transaction.

RISK ENGINE
- Cohort selects the number of sampled loans used by the portfolio scenario.
- Default probability, pairwise default correlation, bond recovery, tail confidence and capital charge are explicit user-set assumptions.
- Scenario capital is a hypothetical what-if only and is not counted by the approval gate.
- Outputs include expected credit loss, VaR, Expected Shortfall, required stress capital, risk-adjusted margin, break-even PD, loss distribution and exact scenario table.
- The decision remains REJECT until mature loan outcomes, calibrated PD, out-of-time validation and actual committed capital exist.
- The contract's maximum borrower-bond shortfall is displayed. Future trader P&L never reduces that loss.

BORROW
- Enter an ENS name or up to four EVM addresses. Check wallet history retrieves available public evidence.
- ENS displays the resolved name/address group. Every additional controller must provide scoped wallet consent before submission.
- Review the evidence row, observation cutoff, linked wallet set and terms before signing.
- Escrow bond and request sends wallet-authorized transactions. Confirmed requests appear below.
- Request records show attestation status, terms, deadline, evidence digest and transaction history. The borrower can cancel an unfunded request, repay a funded loan before maturity or settle a matured default.

LEND
- Requests are read from the trader-credit contract. Refresh reloads chain state.
- Discover on Arkiv queries evidence packets and verifies claims against the contract request.
- An eligible request displays borrower, score, principal, total due, bond, deadline and maximum principal loss.
- The lender acknowledges the possible principal loss before funding. Funding uses a separate wallet and exact token approval.
- A borrower can repay by maturity. After maturity, any connected account can settle default. Request cards show loan events and transaction hashes.
- Local curator attestation is labeled Local forwarder; it is not a Chainlink CRE execution receipt.
- Publish on Arkiv requires the borrower wallet and Rabdi test-network fees. Publishing does not move loan funds.

WHITEPAPER
- In-app Whitepaper describes implemented flows, benchmark limits, integrations and current risks.
- Documentation opens repository developer documentation. Data returns to the benchmark.

GLOBAL CONTROLS
- Header displays page, configured network, refresh and connected account.
- Wallet dialog supports an injected browser wallet. Local demo mode exposes labeled borrower, lender, resolver accounts and the local test-USDC faucet.
- Offline state pauses transactions; saved balances are not used as live chain state.
- Transaction notices report signing, pending, confirmed or failed state and link to a receipt when available.

DATA BOUNDARIES
- Benchmark covers sampled Polymarket wallets and markets, not a venue-wide census.
- Daily wallet P&L is not ROI because complete equity and opening bankroll are unavailable.
- The benchmark has no mature AQRA repayment/default labels or timestamped trader probability forecasts. It does not report PD, lender returns or Brier skill.
- The schedule, source gaps, boundary audits and checksums are recorded under work/underwriting. The browser serves the checked-in run JSON.
- This is unaudited local/testnet software. No production lending pool, external position custody, public CRE execution receipt or mainnet loan is claimed.
