# Data Model, Public API and Integration Contracts

**Source-of-truth rule:** contracts hold economic state; database holds indexed, reorg-aware projections and optional research data. API can never issue a collateral proof that substitutes for `FloorVerifier.verifyPair`.

## 1. Data types

Use `bigint` / decimal strings for onchain amounts. `USDC` base units = integer with 6 decimals; `strike` and `price` integers with observation-specific `priceDecimals`. Persist raw uints as `numeric(78,0)` or text strings; never persist chain financial values as JS floating-point.

| `external_markets` | `(venue,external_id)` | title, rules_text, observed_at, source_uri, license, status | untrusted feed |

| `system_health` | `(service,checked_at)` | latency_ms, status, details | operations |

**Reorg handling:** keep raw orphaned block records for audit, but only canonical logs project as current state. On block mismatch, rewind to latest stable ancestor and reapply. Verify public chain finality expectations; do not use a magic `12 confirmations` across all chains.

## 3. Suggested HTTP endpoints — read only, except optional test-only admin

| Method | Endpoint | Returns | Security |
|---|---|---|---|
| GET | `/api/v1/health` | chain/API/indexer/feed statuses | no private keys |
| GET | `/api/v1/config` | allowed networks, collateral, contract code hashes, versions | signed/versioned static config |
| GET | `/api/v1/observations` | paginated observation directory | validated filters |
| GET | `/api/v1/markets` | onchain market metadata + supported flags | source-of-truth chain |
| GET | `/api/v1/markets/:id` | one market + all observation references | read only |
| POST | `/api/v1/proof/preview` | deterministic scenario chart + chain view verification | **not an authorization**; Zod payload |
| GET | `/api/v1/vaults/:owner` | wallet-owned positions | chain-backed indexed state |
| GET | `/api/v1/vaults/:id` | custody, floor, loan lien | indexed + direct verification option |
| GET | `/api/v1/loans` | loan book with pagination and statuses | read only |
| GET | `/api/v1/loans/:id` | loan terms, explorer links, settlement receipts | read only |
| GET | `/api/v1/research/markets` | external Gamma metadata (not collateral eligible) | TTL, license/provenance |
| GET | `/api/v1/activity` | indexed events timeline | filtered for address |
| GET | `/api/v1/metrics` | TVL/collateral exposure/settlement stats | aggregate |

**All writes** such as `lockPair`, `fundLoan` and `settle` are wallet-signed directly through `viem` and generated ABIs. Do not create privileged API endpoints that call onchain money functions on users' behalf.

## 6. Polymarket Gamma adapter — research ONLY

### Source characteristics

The Senthos implementation uses a backend-driven curated Polymarket feed for market discovery. Implement our read-only adapter separately behind rate limiting, Zod validation and a cache. Treat the user's browser region, exchange terms, and data redistribution permissions as compliance requirements.

### Normalization

`externalId`, `marketQuestion`, `outcomeLabels`, `conditionId`, `resolutionSource`, `rules`, `endDate`, `livePrice`, `bid`, `ask`, `liquidity`, `updatedAt`, `sourceUri`, `venue`, `eligibility='RESEARCH_ONLY'`.

### Strict separation

External markets can populate searchable cards and 'candidate logical relationship' graphs. They cannot be used in `lockPair` because they are not the approved ERC-1155 tokens with shared observation ID and payout/cancel policy on Floor Protocol's chain. A future Polygon adapter requires exact onchain CTF condition/oracle verification and independent custody testing.

## 7. Event indexing (example)

```ts
const cursor = { chainId, finalizedBlock, blockHash };
for (const block of stableBlocksAfter(cursor)) {
  assertCanonicalParent(block);
  const logs = await getLogsForKnownContracts(block);
  await db.transaction(async tx => {
    for (const log of logs) {
      await upsertLog(tx, log); // unique chainId+blockHash+txHash+logIndex
      await applyProjection(tx, decodeKnownEvent(log));
    }
    await updateCursor(tx, block.number, block.hash);
  });
}
```

No offchain 'settled' label may overwrite a different contract state. Frontend transaction state resolution: `pending → included → confirmed → indexed`, with `reverted` and `reorged` as explicit exceptions.

## 8. Observability and metrics

Request IDs, structured JSON logs, chain ID, application version, proof rule version, finalized block lag, oracle age, external quote stale ratio, `loan_funding_failed_total`, `settlement_failed_total`, `vault_accounting_mismatch_total`, `indexer_reorg_total`, API p95. Do not log seed phrases, access tokens or borrower secrets.
