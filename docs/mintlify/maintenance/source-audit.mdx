## Documentation decision

This site documents the checked-in implementation without changing monetary contracts or silently rewriting the original blueprint. `MECHANISM_AND_PROOFS.md` remains the payout authority; implementation decisions resolve documented scope/timing/rounding ambiguities. Generated ABI references, not proposed signatures, are the callable interface reference.

This is a documentation/source review, not a new security audit or full rerun of historical release gates.

## Known residual limitations, not silently repaired

- Some UI copy hardcodes local/mock asset and test resolver language; Sepolia-aware labels need a separately tested UI change. Example: proof and settlement metadata currently name trusted test resolver, and credit badges assume 20% despite reading dynamic caps.
- Operations displays a one-hour cancellation grace even though its feed-mode new-pair code uses one day. Read actual `cancelAfter` onchain.
- API collections are bounded, not cursor-paginated. Their total is the snapshot-window count, not a protocol-global count.
- Proof preview pins the verifier query, then fetches a separate snapshot for scenario metadata; it is not an atomic cross-response snapshot. Scenarios may exist even when `valid` is false.
- Preview payload size guard trusts declared Content-Length; malformed JSON/RPC errors reach generic 500. Do not claim hardened public request limits/rate limits.
- Example `NEXT_PUBLIC_` connection values are unused by the current provider; Operations/manifest config is authoritative.
- Existing public read/fork evidence cannot be upgraded to a public deployment claim.
- API and local orchestration ports are not fully parameterized end-to-end.

These observations do not authorize relaxing contract guards. Any financial-rule change needs an explicit ADR/spec update and negative, boundary, conservation and lifecycle tests before implementation.
