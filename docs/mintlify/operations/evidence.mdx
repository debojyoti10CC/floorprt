## Trader-performance benchmark

The current sample is checked in as [`apps/web/public/underwriting/run.json`](https://github.com/debojyoti10CC/floorprt/blob/main/apps/web/public/underwriting/run.json). It records the benchmark profile, capture time, sampling plan, dataset hash, source coverage, eleven completed forward rounds, wallet-month rows and policy outcomes. The UI reads this artifact; it does not fabricate live results.

Re-run the deterministic replay from the repository root:

```bash
pnpm underwriting:replay --benchmark
```

To recollect missing source data before replay, use `pnpm underwriting:benchmark`. Collection makes external requests and can produce a changed artifact. Record the new artifact hash and capture manifest with any reported result. The benchmark measures trader P&L and activity only. It does not contain loan repayment labels or prove credit performance.

## Local loan demonstration

The local flow described in [Quickstart](/quickstart) submits real transactions to a loopback Anvil chain using test USDC. Receipts and state changes prove that the local contract path executed. Local role impersonation is an explicit developer shortcut; it is not borrower consent, a public-chain receipt or a real-value transfer.

The checked-in `evidence/` directory and [`RELEASE_EVIDENCE.md`](/specifications/RELEASE_EVIDENCE) preserve a **historical Floor Protocol verification run** from a previous product direction. Its screenshots, test counts, fork results and outcome-token receipts do not validate the current trader-credit app or its contracts. They must not be presented as AQRA loan evidence.

## External integrations

Current code paths and proven executions are different claims. No successful official CRE CLI simulation, public CRE write, Arkiv Rabdi write/read receipt, public AQRA loan deployment, or Arc Studio project is recorded. Do not use source code, a mock, a screenshot or a local transaction as proof of those external executions. See the [submission evidence checklist](/specifications/ETHGLOBAL_SUBMISSION).

## What a new release record must contain

- Exact commit, command, tool versions and exit status for each check actually run.
- Benchmark artifact hash, collection manifest, capture window and policy parameters.
- Local or public chain ID, contract code identity, transaction hash, event and token movement for every claimed loan lifecycle step.
- Separate labels for local Anvil, public testnet, official workflow simulation and live DON execution.
- Dependency and security review date; no claim of an independent audit unless one has been completed.
