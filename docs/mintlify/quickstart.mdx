## Start the local stack

Use Node 24 and pnpm 10.20.0.

```bash
pnpm install --frozen-lockfile
pnpm dev
```

| Service | Local address |
| --- | --- |
| AQRA app | `http://127.0.0.1:3000/` |
| Read API | `http://127.0.0.1:8787/api/v1/health` |
| Anvil RPC | `http://127.0.0.1:8545`, chain 31337 |

The runner builds and deploys contracts, seeds local test-USDC and starts the API and app. Keep Anvil on loopback. Local roles and faucet funds are developer tools, not customer accounts or real-value USDC.

## Run the interactive lifecycle

1. Open **Borrow** and expand **Run the contract demo**.
2. Read the local-only notice and confirm that this uses a sampled wallet impersonated only by Anvil.
3. Choose **Create local test request**. The borrower bond is escrowed in a local-chain transaction.
4. Choose **Connect local curator**. In the request card, choose **Submit local report**.
5. Choose **Connect local lender**. Review principal, due, bond and the shortfall. Check the loss acknowledgement, then choose **Fund**.
6. Choose **Connect local borrower**. On the funded request, choose **Repay from local demo borrower**. The test action impersonates that borrower only on loopback Anvil.
7. Review each confirmed transaction and the updated request state. A matured request can be settled as default instead of repaid; do not advance the clock unless you want to demonstrate that alternative.

The interactive path uses a test account selected from the captured sample and does not represent real borrower consent. To try the wallet-signed borrower path, connect a local browser wallet, load its own ENS name or wallet evidence, and sign its request directly.

## Reproduce the wider replay

```bash
pnpm underwriting:replay --benchmark
```

This replays captured source data without making new collection requests. To collect missing captures and replay the fixed sample, run `pnpm underwriting:benchmark`. The sample measures following-month trader P&L; it is not credit repayment evidence. See [Trader credit](/specifications/TRADER_CREDIT), [risk model](/specifications/risk-engine) and the [whitepaper](/whitepaper).
